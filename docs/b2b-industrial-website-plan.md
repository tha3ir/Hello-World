# خطة تنفيذ موقع شركة B2B صناعية — معدات ورش السيارات وأفران الدهان وتجهيز مراكز الخدمة

> **المنصة:** Hostinger Managed WordPress + Elementor
> **السوق:** السعودية (الرياض أولًا) مع قابلية التوسع للخليج
> **المستوى:** خطة مكتوبة لمبتدئ غير تقني، بجودة تنفيذ خبير
> **آخر تحديث:** 2026-07-20

---

## 1) Executive Summary — الملخص التنفيذي

### ماذا سنبني؟
سنبني موقع شركة صناعية B2B هدفه الأول **توليد طلبات عروض أسعار (RFQ)** وليس البيع المباشر أونلاين. الموقع سيكون:

- **كتالوج احترافي** لمعدات ورش السيارات: أفران الدهان، غرف التحضير، الروافع، معدات سحب الشاسيه، تجهيز مراكز الخدمة الكاملة.
- **آلة توليد عملاء (Lead Machine):** كل صفحة تنتهي بزر "اطلب عرض سعر" أو "تواصل واتساب".
- **مصدر ثقة:** مشاريع منفذة، عملاء، ضمانات، خدمة ما بعد البيع.
- **مُهيّأ للظهور** في Google وفي محركات الإجابات بالذكاء الاصطناعي (ChatGPT, Gemini, Perplexity, AI Overviews).

### لماذا هذه البنية مناسبة لشركة B2B صناعية؟
عميل الـ B2B (صاحب ورشة، مدير مشتريات، مستثمر مركز خدمة) لا يشتري بنقرة واحدة. رحلته: **يبحث → يقارن المواصفات → يتحقق من الثقة → يطلب عرض سعر → يتفاوض**. لذلك بنية الموقع الصحيحة هي: صفحات فئات منتجات قوية + صفحات منتجات بمواصفات تفصيلية + صفحات مشاريع وعملاء + نموذج RFQ سهل جدًا. هذه البنية تخدم البحث (SEO) والثقة (Trust) والتحويل (Conversion) في آن واحد.

### لماذا Hostinger Managed WordPress + Elementor مناسب لك كمبتدئ؟

| العامل | لماذا يناسبك |
|---|---|
| **Managed WordPress** | Hostinger يتولى عنك التحديثات الأساسية، النسخ الاحتياطي اليومي، شهادة SSL، والحماية الأساسية — أي أن الأمور التقنية الخطرة "مُدارة" بدلًا منك. |
| **سيرفرات LiteSpeed** | خوادم Hostinger تعمل بتقنية LiteSpeed السريعة مع إضافة كاش جاهزة، فتحصل على سرعة ممتازة بدون خبرة تقنية. |
| **Elementor** | محرر سحب وإفلات بصري — تبني الصفحات بالماوس بدون كود، ويدعم العربية RTL بشكل ممتاز. |
| **WordPress** | أكبر نظام إدارة محتوى في العالم؛ أي مشكلة تواجهها لها حل موثق، وأي مطور مستقبلًا يستطيع العمل عليه. |
| **التكلفة** | التكلفة الإجمالية للسنة الأولى تقريبًا 700–1,500 ريال (استضافة + دومين + Elementor Pro) — منخفضة جدًا مقارنة بقيمة صفقة واحدة من فرن دهان. |

**الخلاصة:** لا نبني متجرًا إلكترونيًا معقدًا، بل موقع شركة + كتالوج + نظام RFQ. هذا أبسط وأسرع وأنسب لطبيعة عملك.

### ما يجب تجنبه كمبتدئ (مهم جدًا)
1. ❌ **القوالب الجاهزة الضخمة** (Avada, WoodMart, Porto...) — تبدو مغرية لكنها بطيئة ومعقدة وتقيدك.
2. ❌ **WooCommerce الآن** — أنت لا تبيع أونلاين، تجمع RFQ. المتجر يضاعف التعقيد بلا فائدة حالية.
3. ❌ **تعدد إضافات لنفس الوظيفة** (إضافتا SEO، إضافتا كاش) — تعارضات وأعطال.
4. ❌ **إضافات المؤثرات البصرية** (سلايدرات ضخمة، جسيمات متحركة) — تقتل السرعة ولا تبيع فرن دهان.
5. ❌ **موقع ثنائي اللغة من اليوم الأول** — ابدأ عربي فقط (قرار مُعلَّل في القسم 8).
6. ❌ **Page builders إضافية** أو "حزم عناصر Elementor" (Element Pack وأمثالها) — Elementor Pro يكفي.

## 4) Step-by-Step Implementation Plan — خطة التنفيذ خطوة بخطوة

> مدة التنفيذ الواقعية لمبتدئ: **3–4 أسابيع** بمعدل ساعتين يوميًا. لا تستعجل الإطلاق قبل اكتمال الفحص.

### المرحلة أ: التأسيس (اليوم 1–2)

#### الخطوة 1: شراء الاستضافة والدومين
- **الهدف:** امتلاك السيرفر والعنوان.
- **عمليًا:** ادخل hostinger.com → اختر باقة **Business** لمدة 12 شهرًا → أثناء الشراء سجّل الدومين المجاني (`yourcompany.com`) → أكمل الدفع → فعّل حسابك من رسالة البريد.
- **التحقق:** تدخل لوحة hPanel وترى الدومين "Active" والاستضافة "Active".
- **أخطاء شائعة:** شراء الدومين من شركة والاستضافة من أخرى (يعقّد الربط عليك)؛ اختيار باقة Premium لتوفير بسيط ثم خسارة النسخ اليومي؛ كتابة الدومين بخطأ إملائي (لا يمكن تعديله!).

#### الخطوة 2: تثبيت WordPress وتفعيل SSL
- **الهدف:** موقع WordPress يعمل بأمان على https.
- **عمليًا:** من hPanel → Websites → Add Website → WordPress → أنشئ اسم مستخدم للإدارة (ليس "admin"!) وكلمة مرور قوية 16+ حرفًا (احفظها في مدير كلمات مرور) → انتظر التثبيت → من hPanel تأكد أن SSL مفعّل وأن خيار "Force HTTPS" مفعّل.
- **التحقق:** افتح `https://yourdomain.com` وترى القفل 🔒 في المتصفح، وافتح `http://` (بدون s) وتأكد أنه يحوّلك تلقائيًا إلى https. تدخل لوحة التحكم من `yourdomain.com/wp-admin`.
- **أخطاء شائعة:** اسم مستخدم "admin" (هدف أول للاختراق)؛ ترك الموقع بدون Force HTTPS فيُفهرس بنسختين.

#### الخطوة 3: إعدادات WordPress الأولية
- **الهدف:** أساس نظيف وصحيح للعربية.
- **عمليًا:** من wp-admin: (1) Settings → General: اللغة العربية، المنطقة الزمنية Riyadh، اسم الموقع = اسم الشركة، والوصف = سطر تعريفي. (2) Settings → Permalinks → اختر **Post name** (روابط نظيفة). (3) Settings → Reading → تأكد أن "Discourage search engines" **غير** مفعّل الآن؟ — لا، **فعّله مؤقتًا** حتى الإطلاق ثم ألغِه (خطوة 17). (4) احذف الإضافات والقوالب المثبتة مسبقًا التي لن تستخدمها.
- **التحقق:** الروابط تظهر بشكل `yourdomain.com/page-name` وليس `?p=123`، ولوحة التحكم بالعربية RTL.
- **أخطاء شائعة:** نسيان Permalinks (تغييرها بعد الإطلاق يكسر الروابط)؛ نسيان إلغاء "Discourage search engines" يوم الإطلاق (أشهر خطأ يمنع الظهور في Google!).

#### الخطوة 4: تثبيت القالب والإضافات
- **الهدف:** الحزمة التقنية كاملة (قائمة القسم 3).
- **عمليًا:** Appearance → Themes → Add New → ابحث "Hello Elementor" → Install → Activate. ثم Plugins → Add New وثبّت واحدة تلو الأخرى: Elementor، Rank Math SEO، LiteSpeed Cache، Wordfence، UpdraftPlus، FluentSMTP، Site Kit by Google، Converter for Media. ثم ارفع Elementor Pro (ملف zip من حسابك في elementor.com) وفعّله بالترخيص.
- **التحقق:** قائمة Plugins تُظهر الجميع "Active" بلا رسائل خطأ، وElementor Pro يظهر "License: Active".
- **أخطاء شائعة:** تثبيت إضافات إضافية "لأنها تبدو مفيدة"؛ تنزيل Elementor Pro من مواقع مقرصنة (أبواب خلفية للاختراق — لا تفعلها أبدًا).

### المرحلة ب: الهوية والبنية (اليوم 3–6)

#### الخطوة 5: إعداد Elementor والهوية البصرية
- **الهدف:** ألوان وخطوط موحدة تلقائيًا في كل الموقع.
- **عمليًا:** (1) Elementor → Settings → Features: عطّل ما لا تحتاجه. (2) افتح أي صفحة بـ Elementor → القائمة ☰ → **Site Settings**: حدّد Global Colors (أزرق صناعي داكن مثل `#0F3057` أساسي + برتقالي/أصفر تنبيه مثل `#F2A900` للأزرار + رمادي فاتح للخلفيات) وGlobal Fonts (ارفع IBM Plex Sans Arabic من Elementor → Custom Fonts أولًا: وزن 400 و700). (3) حدّد Layout: عرض المحتوى 1140px. (4) ارفع الشعار وأيقونة الموقع Favicon.
- **التحقق:** أنشئ صفحة تجريبية، أضف عنوانًا وزرًا — يظهران تلقائيًا بخطك وألوانك بدون تعديل يدوي.
- **أخطاء شائعة:** اختيار ألوان يدويًا في كل قسم بدل Global Colors (كابوس عند أي تعديل لاحق)؛ استخدام 4 خطوط (بطء وتشتت بصري).

#### الخطوة 6: بناء Header وFooter
- **الهدف:** رأس وتذييل موحدان في كل الصفحات.
- **عمليًا:** Templates → Theme Builder → Header → Add New: شعار يمين (RTL) + قائمة (الرئيسية، المنتجات، الخدمات، المشاريع، من نحن، اتصل بنا) + زر بارز "اطلب عرض سعر" + رقم الهاتف. اضبط نسخة الجوال (قائمة همبرغر). ثم Footer: عن الشركة باختصار، روابط سريعة، معلومات التواصل الكاملة (عنوان الرياض، هاتف، بريد)، أيقونات التواصل، وسطر الحقوق.
- **التحقق:** افتح 3 صفحات مختلفة على الكمبيوتر والجوال — الهيدر والفوتر يظهران بشكل صحيح، وزر عرض السعر واضح دائمًا.
- **أخطاء شائعة:** قائمة بـ 10 عناصر (الحد الأقصى 6–7)؛ نسيان اختبار الجوال (60%+ من زوارك جوال).

#### الخطوة 7: إنشاء الصفحات والبنية
- **الهدف:** كل صفحات الموقع (هيكل القسم 5) منشأة ومربوطة.
- **عمليًا:** Pages → Add New لكل صفحة من شجرة القسم 5 مع ضبط الرابط (Slug) بالإنجليزية كما في القسم 8 (مثال: صفحة "أفران الدهان" برابط `/paint-booths/`). ابنِ محتوى كل صفحة بـ Elementor حسب إطار القسم 6. ابدأ بالرئيسية (wireframe القسم 7) ثم صفحات الفئات ثم البقية. اربط القائمة من Appearance → Menus.
- **التحقق:** كل صفحة تفتح من القائمة، لا توجد روابط مكسورة، والروابط Slugs إنجليزية قصيرة.
- **أخطاء شائعة:** روابط عربية في الـ URL (تتحول لرموز غريبة عند النسخ %D8%A3...)؛ نسخ صفحة وتعديلها ونسيان تغيير الرابط والعنوان.

#### الخطوة 8: إعداد النماذج (Forms)
- **الهدف:** نموذج RFQ يعمل ويصلك فورًا.
- **عمليًا:** (1) اضبط FluentSMTP أولًا: أنشئ بريد `sales@yourdomain.com` من hPanel → Emails، ثم FluentSMTP → أدخل بيانات SMTP الخاصة بـ Hostinger → أرسل رسالة اختبار. (2) في صفحة "اطلب عرض سعر" أنشئ نموذج Elementor Pro بحقول: الاسم*، اسم المنشأة، الجوال*، المدينة، نوع المعدات المطلوبة (قائمة منسدلة: فرن دهان / غرفة تحضير / روافع / سحب شاسيه / تجهيز مركز كامل / أخرى)، تفاصيل الطلب. (3) Actions After Submit: إرسال Email إلى بريد المبيعات + **Redirect** إلى صفحة الشكر `/thank-you/`. (4) كرر نموذجًا مختصرًا (اسم + جوال + المطلوب) في أسفل صفحات المنتجات.
- **التحقق:** أرسل 3 اختبارات حقيقية من جوالك — تصل الرسائل خلال دقيقة إلى بريد المبيعات (وليس Spam) ويحوّلك النموذج لصفحة الشكر.
- **أخطاء شائعة:** الاكتفاء بإعداد النموذج دون SMTP (الرسائل لن تصل)؛ نموذج بـ 10 حقول إلزامية (يقتل التحويل — 4 حقول إلزامية كحد أقصى)؛ نسيان الـ Redirect لصفحة الشكر (سنحتاجها لقياس التحويلات).

### المرحلة ج: التتبع والفهرسة (اليوم 7–9)

#### الخطوة 9: إعداد التحليلات (GA4 عبر Site Kit)
- **الهدف:** قياس كل زائر من اليوم الأول.
- **عمليًا:** Site Kit → Start Setup → سجّل دخول بحساب Google الخاص بالشركة → وافق على الصلاحيات → فعّل Analytics من داخل Site Kit (سينشئ حساب GA4 وربطه تلقائيًا).
- **التحقق:** افتح موقعك من جوالك، ثم GA4 → Reports → Realtime — ترى زائرًا واحدًا (أنت).
- **أخطاء شائعة:** الربط بحساب Google شخصي قد تفقده؛ تثبيت كود GA4 يدويًا مع Site Kit معًا (ازدواج عدّ الزوار).

#### الخطوة 10: إعداد Search Console
- **الهدف:** تعريف Google بموقعك رسميًا.
- **عمليًا:** يتم تلقائيًا ضمن إعداد Site Kit في الخطوة السابقة (يتحقق من الملكية بدون أي كود يدوي). ادخل search.google.com/search-console وتأكد أن الموقع ظاهر.
- **التحقق:** في Search Console يظهر موقعك "Verified" وتستطيع فتح تقاريره.
- **أخطاء شائعة:** إضافة النطاق يدويًا بصيغة مختلفة (www مقابل بدون www) — اترك Site Kit يتولى الأمر.

#### الخطوة 11: إعداد Sitemap
- **الهدف:** خريطة تُسهّل على Google اكتشاف كل صفحاتك.
- **عمليًا:** Rank Math ينشئها تلقائيًا على `yourdomain.com/sitemap_index.xml`. من Rank Math → Sitemap Settings: استثنِ صفحة الشكر و404 من الخريطة. ثم في Search Console → Sitemaps → أضف `sitemap_index.xml` → Submit.
- **التحقق:** Search Console يعرض الحالة "Success" وعدد الصفحات المكتشفة منطقيًا.
- **أخطاء شائعة:** إرسال الخريطة قبل إلغاء "Discourage search engines"؛ ترك صفحات الشكر والاختبار داخل الخريطة.

#### الخطوة 12: إعداد robots.txt
- **الهدف:** توجيه محركات البحث لما يُزحف وما لا يُزحف.
- **عمليًا:** Rank Math → General Settings → Edit robots.txt وتأكد أنه يحتوي (اطلب من Claude Code توليده — القسم 14):
  - سماحًا عامًا بالزحف، ومنعًا لـ `/wp-admin/` (مع السماح بـ admin-ajax.php)، ومنع صفحة الشكر `/thank-you/` من الزحف، وسطر `Sitemap:` برابط الخريطة.
- **التحقق:** افتح `yourdomain.com/robots.txt` وترى المحتوى، واختبره بأداة فحص robots في Search Console.
- **أخطاء شائعة:** سطر `Disallow: /` كامل (يمنع الموقع كله من Google!)؛ منع ملفات CSS/JS من الزحف (يشوه فهم Google لموقعك).

#### الخطوة 13: إعداد Schema (البيانات المنظمة)
- **الهدف:** تعريف Google والذكاء الاصطناعي بكيان شركتك ومنتجاتك بلغة الآلة.
- **عمليًا:** (1) Rank Math → Titles & Meta → Local SEO: املأ اسم الشركة، الشعار، العنوان الكامل بالرياض، الهاتف، ساعات العمل — هذا ينتج LocalBusiness Schema تلقائيًا. (2) لكل صفحة منتج: Rank Math في محرر الصفحة → Schema → اختر Product واملأ الاسم والوصف والعلامة. (3) لأقسام FAQ: استخدم FAQ Schema من Rank Math أو مقطع JSON-LD مخصص يولده لك Claude Code (برومبت جاهز في القسم 14) وتضعه عبر ودجت HTML في Elementor.
- **التحقق:** افحص أهم 5 صفحات بأداة `validator.schema.org` وبأداة نتائج Google المنسقة — بلا أخطاء (التحذيرات Warnings مقبولة).
- **أخطاء شائعة:** تكرار نفس الـ Schema مرتين (من إضافتين)؛ كتابة أسعار وهمية في Product Schema (اتركه بدون سعر مع `offers` من نوع طلب عرض سعر أو احذف الأسعار).

#### الخطوة 14: الصور والسرعة
- **الهدف:** موقع يفتح في أقل من ~2.5 ثانية.
- **عمليًا:** طبّق خطة القسم 11 كاملة: تجهيز الصور قبل الرفع (أبعاد صحيحة + ضغط) → تفعيل WebP من Converter for Media → ضبط LiteSpeed Cache (الإعداد المسبق Preset "Advanced" يكفي) → تفعيل CDN المدمج من hPanel → Lazy Load مفعّل.
- **التحقق:** افحص الرئيسية وصفحة منتج على PageSpeed Insights — النتيجة الميدانية/المخبرية للجوال 80+ وCore Web Vitals ضمن الأخضر (أهداف القسم 11).
- **أخطاء شائعة:** رفع صور من الكاميرا مباشرة (5MB لكل صورة!)؛ تفعيل كل خيارات LiteSpeed القصوى دفعة واحدة ثم انكسار التصميم — فعّل تدريجيًا واختبر.

#### الخطوة 15: النسخ الاحتياطي والأمان
- **الهدف:** طبقتا حماية وطبقتا نسخ.
- **عمليًا:** (1) UpdraftPlus → Settings: جدولة أسبوعية للملفات وقاعدة البيانات → الوجهة Google Drive → صل الحساب → نفّذ أول نسخة يدوية الآن. (2) Wordfence: فعّل الجدار الناري، وفعّل تحديد محاولات الدخول (Login Security → 2FA لحسابك). (3) تأكد من hPanel أن النسخ اليومي مفعّل. (4) فعّل التحديثات التلقائية للإضافات الصغيرة، والتحديث اليدوي لـ Elementor (حدّث بعد أخذ نسخة).
- **التحقق:** ترى ملفات النسخة في Google Drive؛ جرّب تسجيل دخول بكلمة خاطئة 5 مرات — يُحظر المحاول؛ دخولك يتطلب رمز 2FA.
- **أخطاء شائعة:** نسخ احتياطي على نفس السيرفر فقط (إن احترق السيرفر احترقت النسخة)؛ عدم اختبار الاستعادة أبدًا (القسم 12).

### المرحلة د: الإطلاق (اليوم 10–14)

#### الخطوة 16: الاختبار قبل الإطلاق
- **الهدف:** صفر أخطاء ظاهرة يوم الإطلاق.
- **عمليًا:** نفّذ قائمة "قبل النشر" كاملة من القسم 13 — صفحة صفحة، على كمبيوتر وجوال حقيقيين (وليس محاكي المتصفح فقط).
- **التحقق:** كل بنود القائمة ✅.
- **أخطاء شائعة:** الاختبار على جهازك فقط وبمتصفح واحد؛ عدم تجربة النموذج "كعميل حقيقي" من الجوال.

#### الخطوة 17: الإطلاق
- **الهدف:** الموقع مرئي لـ Google والعالم.
- **عمليًا:** (1) Settings → Reading → **ألغِ** تفعيل "Discourage search engines". (2) امسح كل الكاش من LiteSpeed. (3) في Search Console: أرسل الـ Sitemap (إن لم ترسله) واستخدم URL Inspection → Request Indexing للصفحة الرئيسية وأهم 5 صفحات. (4) انشر الموقع على Google Business Profile وقنواتك (واتساب للأعمال، LinkedIn).
- **التحقق:** ابحث في Google عن `site:yourdomain.com` — خلال أيام تبدأ الصفحات بالظهور.
- **أخطاء شائعة:** طلب فهرسة 50 صفحة في يوم واحد (اكتفِ بالمهمة)؛ نسيان مسح الكاش فيرى الزوار نسخة قديمة.

#### الخطوة 18: فحص ما بعد الإطلاق (7 أيام)
- **الهدف:** التقاط أي مشكلة مبكرًا.
- **عمليًا:** نفّذ قائمتي "بعد 24 ساعة" و"بعد 7 أيام" من القسم 13: راقب يوميًا Search Console (أخطاء الفهرسة والتغطية) وGA4 (هل يسجل الزوار؟) واختبر النموذج مرة كل يومين، وراجع سرعة الموقع مجددًا بعد امتلاء الكاش.
- **التحقق:** لا أخطاء حمراء في Search Console، وGA4 يسجل زيارات يومية، ووصلك كل نموذج اختباري.
- **أخطاء شائعة:** إطلاق الموقع ثم نسيانه أسبوعين — أول أسبوع هو أهم أسبوع مراقبة.

## 6) Page-by-Page Content Framework — إطار محتوى كل صفحة

### الصفحة الرئيسية `/`
- **الهدف:** خلال 5 ثوانٍ يفهم الزائر: من أنتم، ماذا تبيعون، لماذا يثق بكم، وكيف يطلب عرض سعر.
- **الجمهور:** جميع الفئات — صاحب ورشة، مدير مشتريات، مستثمر جديد.
- **الأقسام:** (التفصيل الكامل في Wireframe القسم 7).
- **المحتوى:** نصوص قصيرة حاسمة + صور معدات حقيقية + أرقام (سنوات خبرة، مشاريع، عملاء).
- **CTA:** "اطلب عرض سعر" (أساسي) + "تواصل واتساب" (ثانوي).
- **عناصر الثقة:** شعارات عملاء، عدد مشاريع، ضمان، علامات تجارية موزَّعة.
- **SEO intent:** كلمات المظلة العامة: "معدات ورش سيارات في السعودية/الرياض".
- **GEO intent:** فقرة تعريف كيان واضحة: "شركة [الاسم] — مورد معدات ورش السيارات وأفران الدهان في الرياض، السعودية، منذ [سنة]" قابلة للاقتباس حرفيًا من أنظمة الذكاء الاصطناعي.
- **Schema:** `Organization` + `LocalBusiness` + `WebSite`.

### من نحن `/about/`
- **الهدف:** بناء الثقة وتحويل الشركة من "موقع" إلى "كيان حقيقي".
- **الجمهور:** مدير المشتريات والمستثمر الذي يتحقق قبل التوقيع.
- **الأقسام:** قصة الشركة وسنة التأسيس → الرؤية والرسالة → أرقامنا (مشاريع/عملاء/سنوات) → لماذا نحن (الضمان، التركيب، ما بعد البيع) → فريقنا/إدارتنا → موقعنا (خريطة الرياض) → شهاداتنا وشراكاتنا → CTA.
- **المحتوى:** حقائق قابلة للتحقق + صور حقيقية للمعرض/المستودع/الفريق (ليست صور Stock).
- **CTA:** "تعرّف على منتجاتنا" + "تواصل معنا".
- **الثقة:** تاريخ التأسيس، السجل التجاري (ذكره يعزز B2B)، صور حقيقية، أسماء حقيقية.
- **SEO intent:** بحث العلامة التجارية "شركة [الاسم]".
- **GEO intent:** أهم صفحة للكيان — حقائق بصيغة مباشرة: "تأسست عام X"، "مقرها الرياض"، "نفذت +Y مشروعًا". أنظمة AI تسحب من هنا إجاباتها عن "من هي شركة...".
- **Schema:** `AboutPage` + `Organization` (موسع: foundingDate, address, sameAs).

### المنتجات (الصفحة الأم) `/products/`
- **الهدف:** توجيه الزائر لفئته الصحيحة خلال ثوانٍ.
- **الجمهور:** زائر يعرف ماذا يريد تقريبًا.
- **الأقسام:** مقدمة قصيرة (سطران) → شبكة بطاقات الفئات (صورة + اسم + وصف سطر + زر) → لماذا الشراء منا (ضمان/تركيب/صيانة) → CTA عرض سعر.
- **CTA:** بطاقات الفئات نفسها + "لم تجد ما تبحث عنه؟ كلمنا واتساب".
- **SEO intent:** "معدات ورش سيارات"، "تجهيزات ورش".
- **GEO intent:** قائمة فئات نظيفة تسهّل على AI تلخيص "ماذا تبيع الشركة".
- **Schema:** `CollectionPage` + `ItemList`.

### صفحة فئة (مثال: أفران الدهان) `/products/paint-booths/`
- **الهدف:** أهم صفحات الموقع تجاريًا — تستهدف كلمة بحث شرائية مباشرة وتولّد RFQ.
- **الجمهور:** صاحب ورشة/مركز يريد شراء فرن دهان.
- **الأقسام:** H1 + فقرة تعريفية (ما هو فرن الدهان ولمن) → شبكة الموديلات المتوفرة → جدول مقارنة مواصفات الموديلات → ماذا يشمل التوريد (تركيب، تشغيل، تدريب، ضمان) → لماذا أفراننا (مميزات تقنية بلغة بسيطة) → صور تركيبات حقيقية → FAQ خاص بالفئة (5–7 أسئلة: الأسعار تقريبًا كيف تُحدد؟ كم يستغرق التركيب؟ ما المساحة المطلوبة؟ استهلاك الكهرباء؟) → نموذج RFQ مختصر.
- **المحتوى:** 600–1000 كلمة + جداول مواصفات + صور حقيقية.
- **CTA:** "اطلب عرض سعر لفرن دهان" (محدد وليس عامًا) + واتساب.
- **الثقة:** عدد الأفران المركبة، ضمان، صور تركيبات بأسماء مدن.
- **SEO intent:** "افران دهان سيارات"، "فرن دهان للبيع"، "سعر فرن دهان سيارات" — نية شرائية عالية.
- **GEO intent:** الفقرة التعريفية + جدول المواصفات + FAQ = المصدر الذي يقتبسه AI عند سؤال "أفضل مورد أفران دهان في السعودية".
- **Schema:** `CollectionPage` + `FAQPage` + `BreadcrumbList`.

### صفحة منتج فردي `/products/paint-booths/model-a/`
- **الهدف:** إقناع الزائر الجاد بأن هذا الموديل مناسب له وتحويله لـ RFQ.
- **الأقسام:** اسم المنتج + صور متعددة → نبذة (لمن هذا الموديل؟) → **جدول مواصفات فنية كامل** (الأبعاد، الطاقة، الحرارة، تدفق الهواء، العزل...) → ماذا يشمل العرض → الضمان وما بعد البيع → صور/فيديو تركيب حقيقي → منتجات ذات صلة → نموذج RFQ.
- **CTA:** "اطلب عرض سعر لهذا الموديل".
- **SEO intent:** بحث الموديل والنوع المحدد ("فرن دهان ايطالي"، "فرن دهان [مقاس]").
- **GEO intent:** جدول المواصفات هو ذهب GEO — بيانات دقيقة قابلة للسحب المباشر.
- **Schema:** `Product` (بدون سعر، مع brand وdescription) + `BreadcrumbList`.

### الخدمات `/services/` وصفحاتها الفرعية
- **الهدف:** إظهار أنك "شريك حلول" وليس "بائع أجهزة" — أهم تمايز B2B.
- **الأقسام لكل خدمة:** ما الخدمة ولمن → خطوات العمل (1-2-3-4 بشكل مرئي) → ماذا يميزنا → مشاريع ذات صلة → FAQ → CTA.
- **CTA:** "احجز استشارة مجانية" (لصفحة تخطيط الورش) / "اطلب عرض سعر".
- **SEO intent:** "تجهيز ورشة سيارات متكاملة"، "تأسيس مركز خدمة سيارات".
- **GEO intent:** خطوات العمل المرقمة تظهر ممتازة في إجابات AI من نوع "كيف أجهز ورشة".
- **Schema:** `Service` + `FAQPage`.

### مشاريعنا `/projects/`
- **الهدف:** الدليل الاجتماعي الأقوى في B2B — "نفذوا لغيري، سينفذون لي".
- **الأقسام لكل مشروع:** اسم العميل/المدينة → التحدي → ما تم توريده وتركيبه (قائمة) → مدة التنفيذ → صور قبل/بعد → اقتباس من العميل إن أمكن → CTA "أريد مشروعًا مشابهًا".
- **SEO intent:** "تجهيز ورشة في الرياض" + أسماء المدن.
- **GEO intent:** أمثلة ملموسة بمدن وأرقام — تجعل AI يذكرك كمورد "نفّذ فعليًا".
- **Schema:** `Article` أو `CreativeWork` لكل مشروع.

### الأسئلة الشائعة `/faq/`
- **الهدف:** إزالة اعتراضات الشراء + صيد أسئلة البحث الطويلة + تغذية محركات الإجابات.
- **الأقسام:** أسئلة مجمعة بفئات: الأسعار والدفع / التوريد والشحن / التركيب / الضمان والصيانة / التدريب. 15–20 سؤالًا بإجابات 40–80 كلمة لكل منها.
- **SEO/GEO intent:** كل سؤال = استعلام بحث حقيقي ("كم سعر فرن دهان سيارات؟" أجب بنطاق وعوامل التسعير). هذه الصفحة من أكثر ما تقتبسه أنظمة AI.
- **Schema:** `FAQPage` (إلزامي هنا).

### اتصل بنا `/contact/` + اطلب عرض سعر `/request-quote/`
- **الهدف:** contact = كل وسائل التواصل؛ request-quote = صفحة تحويل خالصة.
- **أقسام contact:** نموذج قصير + هاتف (رابط اتصال مباشر) + واتساب + بريد + عنوان + خريطة Google مضمّنة + ساعات العمل.
- **أقسام request-quote:** عنوان مطمئن ("أرسل طلبك وسنرد خلال 24 ساعة عمل") + النموذج الكامل + ماذا يحدث بعد الإرسال (3 خطوات) + وسائل بديلة.
- **Schema:** `ContactPage` + `LocalBusiness`.

### صفحة الشكر `/thank-you/`
- **الهدف:** تأكيد الاستلام + قياس التحويل (كل من يصلها = Lead) + استغلال اللحظة.
- **الأقسام:** "شكرًا، استلمنا طلبك وسنتواصل خلال 24 ساعة" + "للاستعجال: واتساب" + روابط المشاريع والفئات.
- **ملاحظة تقنية:** `noindex` + خارج الـ Sitemap — تُستخدم فقط كهدف تحويل في GA4.

### سياسة الخصوصية + الشروط + 404
- **الخصوصية والشروط:** نصوص قانونية واضحة (يولّدها Claude Code — القسم 14) متوافقة مع نظام PDPL السعودي. مطلوبة للثقة ولسياسات Google.
- **404 المخصصة:** "الصفحة غير موجودة" + بحث + روابط الفئات الرئيسية + زر واتساب — لا تخسر زائرًا وصل بالخطأ.

## 7) Homepage Wireframe — مخطط الصفحة الرئيسية من الأعلى للأسفل

> الأزرار والنصوص أدناه مقترحات جاهزة للاستخدام — عدّل الأسماء والأرقام لتطابق شركتك.

**1. Header (ثابت أعلى الصفحة)**
- الغرض: تنقّل + وصول فوري لعرض السعر.
- العناصر: الشعار (يمين) | القائمة: الرئيسية، المنتجات (قائمة منسدلة بالفئات)، الخدمات، مشاريعنا، من نحن، اتصل بنا | زر برتقالي بارز: **"اطلب عرض سعر"** | رقم الهاتف قابل للنقر.
- ملاحظة SEO/GEO: روابط القائمة نصية حقيقية (ليست صورًا) — تمرر قوة ربط داخلي من كل صفحة.

**2. Hero Section**
- الغرض: الرسالة الكاملة في 5 ثوانٍ.
- النص المقترح (H1): **"تجهيز ورش ومراكز خدمة السيارات في السعودية — معدات، تركيب، وضمان من مصدر واحد"**
- نص فرعي: "أفران دهان، روافع، معدات سحب شاسيه، وتجهيز مراكز خدمة متكاملة — توريد وتركيب وتشغيل مع خدمة ما بعد البيع في الرياض وجميع مناطق المملكة."
- الأزرار: أساسي **"اطلب عرض سعر الآن"** → /request-quote/ | ثانوي **"تصفح المنتجات"** → /products/
- العنصر البصري: صورة حقيقية عالية الجودة لتركيب فرن دهان أو ورشة جهزتموها (ليست صورة Stock أجنبية) — الصورة الحقيقية تبني ثقة تفوق أي تصميم.
- SEO/GEO: H1 يحمل الكلمات الأساسية + الموقع الجغرافي. لا تجعل الـ Hero فيديو ثقيلًا (يقتل LCP).

**3. شريط إشارات الثقة (Trust Bar)**
- الغرض: كسر الشك فورًا بعد الـ Hero.
- المحتوى: 4 أرقام: **"+١٥ سنة خبرة"** | **"+٢٠٠ مشروع منفذ"** | **"ضمان حتى X سنوات"** | **"تركيب وتدريب مجاني"** (استخدم أرقامك الحقيقية فقط).
- العنصر البصري: أيقونات بسيطة + أرقام كبيرة على شريط بلون مغاير.
- GEO: الأرقام المنسوبة للكيان تُقتبس حرفيًا في إجابات AI.

**4. فئات المنتجات الرئيسية**
- الغرض: توجيه كل زائر لفئته خلال نقرة.
- العنوان (H2): "ماذا نورّد ونركّب؟"
- المحتوى: 5–6 بطاقات (صورة + اسم الفئة + سطر وصف + زر "استعرض"): أفران الدهان / غرف التحضير / الروافع / معدات سحب الشاسيه / معدات الخدمة / تجهيز مراكز متكاملة.
- SEO: اسم كل بطاقة = نص رابط Anchor يحمل الكلمة المفتاحية للفئة.

**5. لماذا تختارنا (Why Choose Us)**
- الغرض: التمايز عن المستوردين العشوائيين.
- العنوان (H2): "لماذا تتعامل معنا الورش ومراكز الخدمة؟"
- المحتوى: 4 بطاقات: **مصدر واحد لكل شيء** (معدات + تركيب + تشغيل) / **فنيون متخصصون** (تركيب وصيانة بفريقنا) / **ضمان حقيقي وقطع غيار** / **خبرة السوق السعودي** (نعرف اشتراطات البلديات والدفاع المدني).
- GEO: نقطة "اشتراطات البلديات والدفاع المدني" تمايز محلي قوي يلتقطه AI.

**6. منتجات مميزة (Featured Products)**
- الغرض: عرض "أبطال البيع" مباشرة.
- المحتوى: 3–4 منتجات الأعلى طلبًا (صورة + اسم + أهم 3 مواصفات + زر "التفاصيل وعرض السعر").

**7. القطاعات التي نخدمها**
- الغرض: كل زائر يرى نفسه.
- المحتوى: شريط أيقوني: ورش الدهان والسمكرة / مراكز الخدمة السريعة / وكالات وموزعو السيارات / أساطيل الشركات / محطات الوقود / المشاريع الجديدة.

**8. مشاريعنا (Projects)**
- الغرض: الدليل الاجتماعي.
- العنوان (H2): "مشاريع نفذناها مؤخرًا"
- المحتوى: 3 بطاقات مشاريع (صورة حقيقية + اسم/مدينة + سطر: ماذا تم) + زر "كل المشاريع".

**9. قسم RFQ CTA (شريط تحويل كامل العرض)**
- الغرض: التحويل الرئيسي قبل نهاية الصفحة.
- النص: **"جاهز تجهّز ورشتك أو ترقّي معداتك؟"** — "أرسل تفاصيل مشروعك واحصل على عرض سعر خلال 24 ساعة عمل."
- الأزرار: **"اطلب عرض سعر"** + **"كلمنا واتساب"** (بأيقونة واتساب الخضراء).
- العنصر البصري: خلفية داكنة بلون العلامة + تباين عالٍ للأزرار.

**10. الأسئلة الشائعة المختصرة**
- الغرض: إزالة آخر الاعتراضات + Schema FAQ للرئيسية.
- المحتوى: 4–5 أسئلة (أكورديون): هل التركيب مشمول؟ / كم مدة التوريد؟ / هل يوجد ضمان وقطع غيار؟ / هل تخدمون خارج الرياض؟ + رابط "كل الأسئلة".
- GEO: أجوبة مباشرة من جملتين — وقود محركات الإجابات.

**11. Footer**
- الغرض: معلومات NAP كاملة + روابط + إشارة كيان أخيرة.
- المحتوى: 4 أعمدة: (1) عن الشركة بسطرين + الشعار (2) روابط الفئات الخمس (3) روابط الشركة (من نحن، المشاريع، FAQ، الخصوصية، الشروط) (4) **الاسم والعنوان والهاتف موحدة حرفيًا مع Google Business Profile** + بريد + ساعات عمل + أيقونات التواصل.
- SEO/GEO: تطابق NAP (الاسم/العنوان/الهاتف) بين الموقع وGBP حرفيًا هو أساس الـ Local SEO.

## 8) SEO Plan — خطة الـ SEO

### قرار اللغة أولًا
**ابدأ عربي فقط.** جمهورك السعودي يبحث بالعربية بأغلبية ساحقة عن هذه المعدات، والموقع الأحادي أسهل عليك 3 مرات. أضف الإنجليزية في المرحلة 2 (بعد 3–6 أشهر) لخدمة المشترين الأجانب ومدراء المشتريات — حينها استخدم Polylang مع روابط `/en/` وأوسمة hreflang (تفاصيل في نهاية هذا القسم).

### Keyword Architecture — هندسة الكلمات المفتاحية
المبدأ: **صفحة واحدة = نية بحث واحدة.** هرم الكلمات:

| المستوى | الصفحة | الكلمات المستهدفة (أمثلة) |
|---|---|---|
| المظلة | الرئيسية | معدات ورش سيارات، تجهيز ورش سيارات السعودية، شركة معدات ورش الرياض |
| الفئة | /paint-booths/ | افران دهان سيارات، فرن دهان سيارات للبيع، سعر فرن دهان، غرف دهان السيارات |
| الفئة | /vehicle-lifts/ | روافع سيارات للبيع، رافعة سيارات عمودين، ليفت سيارات للورش |
| الفئة | /chassis-pullers/ | مكينة سحب شاسيه، جهاز شد شاسيه سيارات، بنش سحب شاسيه |
| الفئة | /prep-stations/ | غرفة تحضير دهان، ركن تحضير سيارات |
| الخدمة | /service-center-setup/ | تجهيز مركز صيانة سيارات، تأسيس ورشة سيارات متكاملة، تكلفة تجهيز ورشة |
| محلي | الرئيسية + contact | معدات ورش سيارات الرياض، افران دهان الرياض، تجهيز ورش جدة/الدمام (لاحقًا بصفحات مدن) |
| معلوماتي | المدونة | كيف تختار فرن دهان، اشتراطات فتح ورشة سيارات في السعودية، الفرق بين رافعة عمودين واربعة |

اطلب من Claude Code توليد الشجرة الكاملة (برومبت في القسم 14)، وتحقق من أحجام البحث بأداة Google Keyword Planner (مجانية بحساب Google Ads بدون إنفاق).

### Internal Linking — الربط الداخلي
- الرئيسية تربط لكل الفئات (بطاقات القسم 4 من الـ wireframe).
- كل صفحة فئة تربط: لمنتجاتها + لخدمة التركيب + لمشروع ذي صلة + لسؤالين من FAQ.
- كل مقال مدونة يربط لصفحة الفئة المرتبطة **بنص رابط يحمل الكلمة المفتاحية** ("أفران دهان السيارات" وليس "اضغط هنا").
- Breadcrumbs (فتات الخبز) في كل الصفحات الداخلية: الرئيسية > المنتجات > أفران الدهان — مفعّلة بـ Rank Math.

### URL Structure — بنية الروابط
- إنجليزية، قصيرة، بشرطات: `/products/paint-booths/` ✅ — ليست عربية ولا أرقامًا عشوائية.
- لا تغيّر رابطًا بعد النشر؛ وإن اضطررت فاعمل تحويل 301 من Rank Math → Redirections.

### Meta Titles & Descriptions — قواعد العناوين والأوصاف
- **Title:** 50–60 حرفًا: `الكلمة المفتاحية | فائدة قصيرة | اسم الشركة` — مثال: `أفران دهان سيارات — توريد وتركيب بضمان | شركة [الاسم]`.
- **Description:** 140–160 حرفًا تتضمن الكلمة + الموقع + دعوة: `أفران دهان سيارات إيطالية بمقاسات متعددة مع تركيب وتشغيل وضمان في الرياض وجميع مناطق المملكة. اطلب عرض سعر خلال 24 ساعة.`
- تُكتب لكل صفحة يدويًا في حقول Rank Math — لا تترك التوليد التلقائي. (Claude Code يولّد لك الجدول كاملًا — قسم 14).

### Headings — قواعد العناوين
- H1 واحد فقط لكل صفحة يحمل الكلمة الرئيسية.
- H2 للأقسام، H3 للتفاصيل — تسلسل منطقي بلا قفز (لا H4 بعد H1 مباشرة).
- في Elementor: اضبط "HTML Tag" لكل عنوان يدويًا — الافتراضي قد يكون خاطئًا.

### Image Alt Text — النص البديل للصور
- صف الصورة بواقعية مع الكلمة عند ملاءمتها: `فرن دهان سيارات مقاس 7 متر مركب في ورشة بالرياض` ✅ — وليس حشو كلمات: `فرن دهان فرن دهان سعر فرن` ❌.
- سمِّ ملف الصورة قبل الرفع: `paint-booth-riyadh-installation.webp` وليس `IMG_2183.jpg`.

### Blog Strategy — استراتيجية المدونة
ابدأ بـ 4 مقالات ركيزة (1000–1500 كلمة) ثم مقال شهريًا:
1. "كيف تختار فرن دهان لورشتك؟ دليل شامل" → يربط لفئة الأفران.
2. "تكلفة تجهيز ورشة سيارات متكاملة في السعودية" → يربط لخدمة التجهيز (أقوى مقال RFQ).
3. "اشتراطات فتح ورشة سيارات في السعودية" → زيارات من كل من يؤسس ورشة.
4. "رافعة عمودين أم أربعة أم مقص؟ أيها يناسب ورشتك" → يربط لفئة الروافع.

### E-E-A-T — إشارات الخبرة والموثوقية
- صفحة "من نحن" غنية بالحقائق + كاتب حقيقي باسمه وصفته لمقالات المدونة ("م. فلان — مدير الشؤون الفنية").
- صور حقيقية للتركيبات، أرقام قابلة للتحقق، عنوان فعلي، سجل تجاري.
- توحيد بيانات الشركة في: الموقع + GBP + LinkedIn + أي دليل أعمال.

### Technical SEO Checklist
- [x] HTTPS مفروض على كل الموقع
- [x] نسخة واحدة رسمية (بدون www أو معها — واحدة تحوّل للأخرى)
- [x] Sitemap XML مُرسل لـ Search Console
- [x] robots.txt سليم
- [x] Breadcrumbs + Schema
- [x] سرعة جوال 80+ وCWV أخضر
- [x] لا محتوى مكرر (كل فئة نصها الفريد)
- [x] روابط 404 صفر (افحص بـ Broken Link Checker مرة ثم احذف الإضافة)
- [x] Canonical تلقائي من Rank Math

### Indexing Checklist
بعد الإطلاق: أرسل Sitemap → اطلب فهرسة الرئيسية + الفئات الخمس يدويًا → راقب تقرير Pages في GSC أسبوعيًا → أي صفحة "Discovered - currently not indexed" لأكثر من 3 أسابيع: حسّن محتواها وزد الروابط الداخلية إليها.

### Cannibalization Avoidance — منع تنافس صفحاتك
- لا صفحتين تستهدفان نفس الكلمة ("أفران دهان" للفئة فقط؛ المقال يستهدف "كيف تختار فرن دهان").
- المدونة تستهدف أسئلة، والفئات تستهدف نوايا شراء — خط فاصل دائم.
- إن ظهرت صفحتان لنفس الاستعلام في GSC: ادمج الأضعف في الأقوى مع تحويل 301.

### خطة الثنائية اللغوية (المرحلة 2)
عند الجاهزية: إضافة Polylang (مجانية) → بنية `/en/products/paint-booths/` → ترجمة احترافية (وليست آلية خام) لأهم 10 صفحات فقط → hreflang تلقائي من Polylang + Rank Math → قوائم وهيدر مستقلان للإنجليزية LTR.

## 9) GEO Plan — خطة الظهور في محركات الإجابات والذكاء الاصطناعي

**الفكرة ببساطة:** أنظمة مثل ChatGPT وGemini وAI Overviews تجيب المستخدم مباشرة وتقتبس مصادرها. هدفنا أن يكون موقعك **أسهل مصدر يُفهم ويُقتبس** عندما يسأل أحدهم: "أفضل مورد أفران دهان في السعودية؟" أو "كم تكلفة تجهيز ورشة؟". حسن الحظ: 80% من عمل GEO هو نفسه عمل SEO الجيد — والقواعد التالية هي الـ 20% الإضافية:

### 1. فقرة تعريف الكيان (Entity Definition) — في كل صفحة رئيسية
ضع تعريفًا مباشرًا قابلًا للاقتباس الحرفي في أول الصفحة:
> "شركة [الاسم] هي مورد متخصص في معدات ورش السيارات وأفران الدهان وتجهيز مراكز الخدمة، مقرها الرياض، السعودية، وتخدم جميع مناطق المملكة منذ عام [X] بأكثر من [Y] مشروعًا منفذًا."

قاعدة: **حقيقة → جملة كاملة → قابلة للنسخ دون سياق.** الجمل الغامضة التسويقية ("رواد التميز في عالم الجودة") صفر قيمة لـ GEO.

### 2. FAQ Blocks — في كل صفحة فئة وخدمة
- سؤال بصيغة بحث المستخدم الحقيقية + إجابة مباشرة في أول جملة ثم التفصيل.
- مثال: **"كم سعر فرن دهان السيارات في السعودية؟"** → "تتراوح أسعار أفران الدهان عادة بين [نطاق] ريال حسب المقاس ونظام الحرارة وبلد الصنع؛ العوامل الأساسية المؤثرة هي: ..." — إجابة كهذه تُقتبس نصًا.
- كل FAQ مغطى بـ FAQPage Schema.

### 3. جداول المواصفات والمقارنات
- جدول مواصفات HTML حقيقي (وليس صورة!) في كل صفحة منتج: الأبعاد، القدرة، الحرارة، الجهد، الاستهلاك.
- جدول مقارنة في كل صفحة فئة (موديل A مقابل B مقابل C) وفي مقالات المقارنة (عمودين مقابل مقص).
- الجداول أسهل بنية يسحبها الذكاء الاصطناعي حرفيًا.

### 4. تعريفات موجزة (Concise Definitions)
ابدأ كل صفحة فئة بتعريف من جملتين: "فرن دهان السيارات هو غرفة معزولة مزودة بنظام تهوية وتسخين متحكم به، تُستخدم لرش وتجفيف دهان السيارات بجودة مصنعية وبيئة خالية من الغبار." — هذا النمط يتصدر إجابات "ما هو...".

### 5. إشارات الثقة للكاتب والشركة
- Organization Schema كامل (الاسم، الشعار، العنوان، الهاتف، sameAs لحسابات التواصل).
- مؤلف حقيقي بصفته الفنية على المقالات.
- تواريخ نشر وتحديث ظاهرة على المقالات.

### 6. اتساق الكيان والموقع الجغرافي (Entity Consistency)
- اسم الشركة **بحروفه الدقيقة** موحد في: الموقع، GBP، Schema، واتساب للأعمال، LinkedIn، أدلة الأعمال.
- العنوان والهاتف حرفيًا متطابقان في كل مكان.
- سبب: أنظمة AI تبني "بطاقة كيان" عنك من مصادر متعددة — أي تضارب يضعف ثقتها.

### 7. الكتالوجات وملفات المواصفات القابلة للتنزيل
- المرحلة 2: PDF كتالوج لكل فئة (مواصفات + صور + بيانات الشركة) في "مركز تحميلات".
- الفائدة المزدوجة: أداة مبيعات B2B ممتازة + محتوى موثق تفهرسه محركات البحث وتقتبسه أنظمة AI.
- قاعدة: محتوى الـ PDF يجب أن يكون موجودًا كـ HTML أيضًا — الـ PDF مكمل وليس بديلًا.

### 8. كتل محتوى قابلة للتلخيص (AI-Summarizable Blocks)
- فقرات قصيرة (2–4 أسطر)، عنوان H2/H3 لكل فكرة، قوائم نقطية للمزايا، خطوات مرقمة للعمليات.
- بعد كل قسم طويل أضف "الخلاصة:" بجملة أو جملتين — هذه الجمل تُلتقط أولًا.
- اكتب أرقامًا دقيقة كلما أمكن ("التركيب خلال 5–7 أيام عمل" وليس "تركيب سريع").

### قياس GEO
شهريًا: اسأل ChatGPT وGemini وPerplexity: "أفضل موردي معدات ورش السيارات في الرياض؟" و"شركات أفران دهان في السعودية؟" وسجّل هل ظهرت ومن ظهر. وراقب في GA4 الإحالات من نطاقات مثل `chatgpt.com` و`perplexity.ai`.

## 10) Google Integration Plan — خطة الربط مع Google

### الترتيب الصحيح (أسهل مسار للمبتدئ)

| المرحلة | الأداة | متى | كيف |
|---|---|---|---|
| 1 | حساب Google للشركة | اليوم 1 | إنشاء عادي + تفعيل التحقق بخطوتين |
| 2 | **Site Kit** | يوم إعداد الموقع | إضافة Site Kit تربط لك Search Console + GA4 من معالج واحد موجّه خطوة بخطوة — هذا هو طريقك الرسمي والأسهل |
| 3 | Search Console | تلقائي عبر Site Kit | التحقق يتم بدون لمس أي كود |
| 4 | GA4 | تلقائي عبر Site Kit | إنشاء الحساب وزرع كود القياس تلقائيًا |
| 5 | Google Business Profile | أسبوع الإطلاق | إنشاء مستقل + تحقق (بريد/فيديو) |
| 6 | GTM | المرحلة 2 (شهر 2) | عند الحاجة لتتبع نقرات متقدم |

### متى يكفي Site Kit ومتى تحتاج GTM؟
- **Site Kit يكفيك** لـ: عدد الزوار، مصادرهم، الصفحات الأكثر زيارة، كلمات البحث (GSC)، وقياس تحويل صفحة الشكر (لأنه مجرد "زيارة صفحة" وGA4 يراها تلقائيًا).
- **تحتاج GTM عندما** تريد قياس نقرات لا تغيّر الصفحة: زر واتساب، زر الاتصال الهاتفي، تحميل كتالوج PDF. GTM يزرع "مستشعرات" على هذه الأزرار دون كود يدوي لكل زر.
- **القاعدة:** أطلق بـ Site Kit فقط. أضف GTM في الشهر الثاني عندما يستقر الموقع — ولا تركّب كود GA4 مرتين (عند اعتماد GTM لاحقًا، انقل قياس GA4 إليه أو أبقه في Site Kit فقط — مصدر واحد للكود).

### منطق تحويل صفحة الشكر (Thank-You Conversion)
1. نموذج Elementor → بعد الإرسال Redirect إلى `/thank-you/`.
2. في GA4: Admin → Events → أنشئ حدثًا مخصصًا `generate_lead` شرطه: `page_location` يحتوي `/thank-you/`.
3. علّم الحدث كـ **Key Event** (تحويل).
4. النتيجة: كل تقاريرك تجيب "كم طلب سعر جاء هذا الشهر؟ ومن أي مصدر؟" — وهذا هو المقياس رقم 1 لنجاح الموقع كله.

### تتبع واتساب والاتصال (المرحلة 2 مع GTM)
- **واتساب:** GTM Trigger من نوع Click على الروابط التي تحتوي `wa.me` → حدث GA4 باسم `whatsapp_click` → Key Event.
- **الاتصال:** نفس الفكرة على الروابط التي تبدأ بـ `tel:` → حدث `call_click`.
- **حل مؤقت قبل GTM:** اجعل زر واتساب الرئيسي يمر عبر صفحة وسيطة `/go-whatsapp/` تحوّل فورًا لواتساب — فتقيس النقرات كزيارات صفحة بدون GTM.

### Google Business Profile — خطوات كاملة
1. google.com/business → أنشئ الملف باسم الشركة **الحقيقي كما هو على الموقع** (بلا حشو كلمات — مخالف للسياسات).
2. الفئة الأساسية: "مورد معدات" / "Equipment Supplier" وأقرب الفئات الثانوية المتاحة (معدات صناعية، قطع غيار...).
3. العنوان الدقيق بالرياض + نطاق الخدمة: كل مناطق المملكة.
4. أضف: رابط الموقع، الهاتف الموحد، ساعات العمل، وصفًا 750 حرفًا بالكلمات المفتاحية طبيعيًا، 15+ صورة حقيقية (المعرض، التركيبات، الفريق).
5. أكمل التحقق → ثم انشر تحديث Post شهريًا (مشروع جديد/وصول شحنة) واطلب تقييم Google من كل عميل راضٍ (أرسل له الرابط المباشر واتساب).
6. اربطه في Site Kit وراقب مكالماته وزياراته.

### العلاقة بين GA4 وSearch Console
- GSC يجيب: "كيف وجدك الناس في Google؟" (استعلامات، مراكز، نقرات) — GA4 يجيب: "ماذا فعلوا داخل الموقع؟" (صفحات، مدة، تحويلات).
- اربطهما (GSC → Settings → Associations أو من Site Kit) فترى استعلامات البحث داخل تقارير GA4.
- روتينك الأسبوعي (15 دقيقة): GSC: استعلامات جديدة + أخطاء تغطية | GA4: عدد `generate_lead` ومصادرها | GBP: مكالمات ورسائل.

## 11) Performance Plan — خطة السرعة وCore Web Vitals

> لماذا نهتم؟ المستخدم يتوقع فتح الصفحة خلال ~ثانيتين، وGoogle يستخدم السرعة عامل ترتيب. موقع بطيء = عملاء وترتيب أقل.

### أهداف Core Web Vitals (على الجوال — الأهم)

| المقياس | معناه ببساطة | الهدف |
|---|---|---|
| **LCP** | متى يظهر أكبر عنصر بالصفحة | ≤ 2.5 ثانية |
| **INP** | سرعة استجابة الموقع لنقراتك | ≤ 200 ملي ثانية |
| **CLS** | هل تقفز العناصر أثناء التحميل | ≤ 0.1 |
| PageSpeed Mobile Score | مؤشر عام | 80+ |

### الخطة عمليًا (بالترتيب)

1. **القالب:** Hello Elementor — محسوم، أخف نقطة بداية ممكنة.
2. **الصور قبل الرفع (أهم عامل منفرد):**
   - أقصى عرض: 1600px لصور Hero، و800px لبطاقات المنتجات.
   - اضغطها قبل الرفع عبر squoosh.app (مجاني من المتصفح).
   - سمِّ الملفات بالإنجليزية الوصفية.
   - قاعدة: لا صورة فوق 200KB، وصورة الـ Hero تحت 300KB.
3. **WebP/AVIF:** إضافة Converter for Media تحوّل كل ما ترفعه تلقائيًا لـ WebP (وفعّل AVIF إن توفر) — توفير 30–70% من الحجم.
4. **Lazy Load:** مفعّل افتراضيًا في WordPress/LiteSpeed للصور أسفل الشاشة — **استثنِ صورة الـ Hero** من الـ lazy load (يجب أن تظهر فورًا لتحسين LCP).
5. **الكاش (LiteSpeed Cache):** فعّل الـ Preset الجاهز "Advanced" ثم تحقق أن الموقع سليم. المزايا الأساسية: Page Cache + Browser Cache + CSS/JS Minify + Critical CSS. أي خيار يكسر التصميم: أطفئه وامسح الكاش وأعد الاختبار.
6. **CDN:** فعّل CDN المدمج مع باقة Hostinger Business من hPanel — يقدّم ملفاتك من أقرب نقطة جغرافية للزائر السعودي.
7. **الخطوط:** خطان كحد أقصى (عربي أساسي + لاتيني للأرقام إن لزم) مرفوعان محليًا عبر Elementor Custom Fonts بصيغة WOFF2 مع `font-display: swap` (خيار جاهز في Elementor) — فلا تنتظر الصفحة تحميل خط من سيرفر خارجي.
8. **تقليل الإضافات:** التزم بقائمة القسم 3 (9 إضافات). كل إضافة جديدة اسأل: "هل تستحق إبطاء الموقع؟" واحذف أي إضافة عطّلتها أكثر من شهر.
9. **التحكم بالسكربتات:** لا تضف كود Facebook Pixel/چاتات مباشرة في الـ Header بلا حاجة. أي سكربت خارجي = بطء. عند إضافة GTM لاحقًا اجعله البوابة الوحيدة للأكواد الخارجية.
10. **فيديوهات:** لا ترفع فيديو على سيرفرك أبدًا — ارفعه على YouTube وضمّنه بطريقة "Lite embed" (صورة تتحول لفيديو عند النقر، ودجت جاهز في Elementor باسم Video مع Lazy Load).

### ماذا أختبر قبل الإطلاق؟
- PageSpeed Insights (pagespeed.web.dev): الرئيسية + صفحة فئة + صفحة منتج — جوال 80+.
- GTmetrix: حجم الصفحة الكلي < 1.5MB وعدد الطلبات < 60.
- اختبار يدوي: افتح الموقع من جوالك ببيانات الجوال (وليس WiFi) — هل يفتح خلال ~2–3 ثوانٍ؟
- بعد شهر: تقرير Core Web Vitals في Search Console (بيانات مستخدمين حقيقية) — كله أخضر.

## 14) Claude Code Execution Mode — طريقة العمل مع Claude Code

### كيف تتعامل معه من البداية
Claude Code هو مساعدك التقني: يكتب لك المحتوى والخطط والأكواد الصغيرة (Schema/robots) وأنت تنفذ اللصق في WordPress وElementor. طريقة العمل الصحيحة:

1. **أنشئ مجلد مشروع** (مثلًا `website-project/`) واعمل منه دائمًا — يحفظ Claude Code كل الملفات فيه وتتراكم لديك "مكتبة المشروع".
2. **أول جلسة: ملف السياق.** أعطه معلومات شركتك مرة واحدة ليحفظها في ملف `company-profile.md`، وكل برومبت لاحق يبدأ بـ "اقرأ company-profile.md ثم...". هذا يوفر عليك إعادة الشرح كل مرة.
3. **مهمة واحدة لكل جلسة** (محتوى صفحة، أو Schema، أو خطة كلمات) — نتائج أدق من طلب كل شيء دفعة واحدة.
4. **راجع دائمًا:** ما ينتجه مسودة خبيرة — راجع الأرقام والأسماء والأسعار قبل النشر، فأنت مصدر الحقيقة عن شركتك.
